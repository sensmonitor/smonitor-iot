# v0.2.2 — PlatformIO and Waveshare A7670E

This release adds PlatformIO as a second way to build and flash the firmware,
a board profile for the Waveshare ESP32-S3-A7670E-4G, and clearer handling of
a missing mobile operator APN. Application behaviour with a configured APN is
unchanged.

## Changes

- **PlatformIO.** `platformio.ini` has one environment per board profile and
  uses the official `platformio/espressif32` platform with the ESP-IDF
  framework (not Arduino). PlatformIO downloads ESP-IDF and the matching
  toolchain on the first build, so no separate ESP-IDF installation is needed.
  A PlatformIO CI workflow builds every environment.
- **Waveshare ESP32-S3-A7670E-4G.** New profile in
  `examples/waveshare_esp32s3_a7670e` and PlatformIO environment
  `waveshare-esp32s3-a7670e`. The modem UART is on GPIO 18 (TX) and 17 (RX);
  the modem is powered by the board's 4G DIP switch, so the firmware does not
  toggle a PWRKEY pin. Set the DIP switches to "4G ON" and "USB OFF" before
  flashing. The board has no dedicated sensor connector; set the I2C pins in
  `sdkconfig.defaults.local`.
- **APN reminder.** The first PlatformIO build creates
  `sdkconfig.defaults.local` from the example. While the APN is empty,
  PlatformIO warns after every build and stops upload
  (`SMONITOR_ALLOW_EMPTY_APN=1` uploads anyway, for example to read the device
  serial before the SIM card is ready). CMake also warns, and the firmware
  repeats the reminder with the device serial every 10 seconds instead of
  logging it once.
- **Board profile selection.** `SMONITOR_BOARD_DEFAULTS` selects the board
  profile and `SMONITOR_DEPENDENCIES_LOCK` keeps a separate component lock file
  per build, so switching boards does not rewrite the committed
  `dependencies.lock`. Both work with PlatformIO and `idf.py`.

## Validation and limitations

- The ESP-IDF and PlatformIO CI workflows build all board profiles, including
  the Waveshare A7670E profile.
- PlatformIO currently provides ESP-IDF 5.5.5; the ESP-IDF build and CI use
  ESP-IDF 5.5.6.
- The Waveshare A7670E profile reuses the SIM7670 compatibility profile. It is
  not a dedicated A7670 driver; GNSS and 2G are not validated.
- Runtime validation on hardware is pending for the Waveshare A7670E profile.
- Component dependencies are unchanged: `smonitor-modem` 0.1.6,
  `smonitor-i2c` 0.1.1, `esp_modem` 1.4.3 and `esp_websocket_client` 1.8.0.

## Upgrading

ESP-IDF users need no changes. To use PlatformIO, install the PlatformIO IDE
extension in VS Code (or PlatformIO Core), set the APN in
`sdkconfig.defaults.local` and run
`pio run -e <environment> -t upload -t monitor`.
