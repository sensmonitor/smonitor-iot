# v0.2.0 — PLC rules

This release adds PLC rules: the device switches its digital outputs
automatically, based on sensor readings, using rules configured in the
SensMonitor application.

## Changes

- New `smonitor_plc` component. Rules are evaluated on every I2C sensor read
  with `>`, `<`, `>=` and `<=` operators. A rule fires only when its threshold
  is crossed and on its first valid sample, so outputs can still be switched
  manually at any time.
- Rules are received with the device configuration and with every sample ack.
  Unchanged rules keep their state; new or edited rules fire again on their
  first sample.
- When several rules fire for the same output on one read, they are applied by
  rule id and the last one wins.
- A failed sensor read is skipped and never causes a false crossing.
- `smonitor_client` owns the outputs: it sets the GPIO through a PLC output
  callback and reports the rule as `plc_rule` with the changed output in the
  same sample, so the server notifies every user who follows the device.
- Sensor ids are parsed from the device configuration; the sensor type to
  sample type mapping is shared by sample payloads and PLC rules.

## Example

Keep a cooler on pin 18 between 22 and 24 °C with two rules:

- Temperature `>=` 24 °C → cooler ON
- Temperature `<=` 22 °C → cooler OFF

The gap between the thresholds prevents constant switching around one value.

## Validation and limitations

- ESP-IDF 5.5.5 compilation for the ESP32-S3 profile passed, including the
  application partition size check, with no new compiler warnings.
- The PLC logic was tested on the host: threshold crossing, first sample,
  hysteresis with two rules, failed reads, unchanged rules from acks, edited
  and disabled rules.
- A local end-to-end test with the SensMonitor API passed: the rule fired, the
  output switched and a push notification was sent.
- Other CI board profiles were not built locally for this release.
- Rules are kept in RAM only. After a restart, PLC is active again once the
  device configuration is received.
- Sensors are matched to samples by type, so two sensors of the same type map
  to the first sample of that type.
- Rules are sent with every sample ack, which increases mobile data usage when
  rules are configured. A compact rules hash is planned.

## Compatibility

- Requires a SensMonitor API with PLC support to use rules. With an older API
  the firmware behaves exactly as v0.1.5.
- Firmware v0.1.5 and older keeps working with the new API and ignores PLC
  rules.
- Flashing over USB is required; the firmware has no OTA update.
